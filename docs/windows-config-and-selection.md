## Repo / Component Selection

### Scope Reminder
The installer must allow the user to choose which parts of the family to install. **Relational-Substrate (RS)** must be excluded by design (it is a separate research project with its own build and runtime model).

**Selectable Components** (proposed grouping for the Inno Setup Components page):

**Core (always recommended)**
- Galeed (trace spine)
- Keturah (capability manifests + future MCP server)
- Cairn-lang (plan language + view composer)

**Runtime Tools**
- Tirzah (memory + retrieval + planner)
- Mahalath (semantic ontology + review)
- Hoglah (LLM job queue + worker)
- Milcah (coherence / specialist engine) – marked "experimental"

**User Interfaces**
- Mahlah (conversational UI for Tirzah)
- Mizpah (trace/log browser)

**Presets** (helpful for the wizard):
- **Minimal** — Core libs + Hoglah + Tirzah
- **Full Family (recommended)** — Everything except Milcah (or include it)
- **With UIs** — Full Family + Mahlah + Mizpah
- **Custom** — user chooses freely

### Technical Implementation in Installer

1. **Inno Setup `[Components]` section**:
   ```ini
   [Components]
   Name: "core"; Description: "Core family libraries (Galeed, Keturah, Cairn-lang)"; Types: full compact custom; Flags: fixed
   Name: "tirzah"; Description: "Tirzah – memory and retrieval engine"; Types: full compact custom
   Name: "mahalath"; Description: "Mahalath – semantic layer"; Types: full custom
   Name: "hoglah"; Description: "Hoglah – LLM execution queue"; Types: full compact custom; Flags: fixed
   Name: "milcah"; Description: "Milcah – coherence & specialist review (experimental)"; Types: full custom
   Name: "uis"; Description: "Web UIs (Mahlah + Mizpah)"; Types: full custom
   ```

2. **Dependency enforcement** (in `[Code]` Pascal section or post-install PowerShell):
   - Tirzah requires core libs.
   - Mahalath + Tirzah should be co-installed for the semantic seam (or at least warn).
   - UIs require their backend (Tirzah for Mahlah, Galeed for Mizpah).

3. **Download / Install logic**:
   - Use `versions.lock` style data (or a JSON manifest shipped with the installer).
   - For each selected component, either:
     - Git clone (if Git is present) from the tag in the lock, or
     - Download pre-built wheel / zip from a release location.
   - Run the equivalent of `install_pinned_tools` and family wheelhouse logic.

4. **User-visible descriptions** should explain what each piece does and its disk / runtime cost.

## Default Local Configuration

The installer must produce a working "out of the box" setup with sensible Windows paths and no manual editing required.

### Recommended Directory Layout

```
%LOCALAPPDATA%\Noa\                  (or user-chosen root)
├── .env
├── config\
│   ├── tirzah\
│   ├── mahalath\
│   └── hoglah\
├── data\
│   ├── queues\
│   ├── logs\
│   └── mongo-data\   (if not using Docker volumes)
├── venvs\                           (if using embedded or system Python)
│   ├── tirzah\
│   ├── mahalath\
│   └── ...
├── python\                          (optional embedded Python)
├── bin\                             (generated .bat launchers)
└── services\                        (NSSM configs, task definitions, etc.)
```

### Generated `.env` (Windows defaults)

Example content generated by the installer (PowerShell templating):

```env
# Noa Windows default configuration
# Generated on first install. Edit as needed.

# Ollama (always external on host)
OLLAMA_BASE_URL=http://localhost:11434

# Mongo (Docker Compose by default – matches compose.yaml)
MONGO_URI=mongodb://localhost:27017
MAHALATH_MONGO_URI=mongodb://localhost:27017
TIRZAH_MONGO_URI=mongodb://localhost:27017
COMPOSE_PROJECT_NAME=noa

# Hoglah
HOGLAH_QUEUE_DIR=%LOCALAPPDATA%\Noa\data\queues
HOGLAH_OUTPUT_DIR=%LOCALAPPDATA%\Noa\data\logs
HOGLAH_DB_PATH=%LOCALAPPDATA%\Noa\data\hoglah.db
HOGLAH_OLLAMA_HOST=http://localhost:11434

# Service backend (see windows-service-options.md)
HOGLAH_SERVICE_BACKEND=nssm

# Semantic seam (Tirzah <-> Mahalath)
MAHALATH_ENABLED=true
MAHALATH_MONGO_DB=mahalath_dev
TIRZAH_MONGO_DB=mnemosyne_dev

# Paths (Windows style – installer expands %LOCALAPPDATA% etc.)
NOA_ROOT=%LOCALAPPDATA%\Noa
```

The installer should:
- Expand environment variables.
- Create all directories.
- Write the file atomically.
- Never overwrite an existing `.env` (offer backup + merge, or "keep existing" option).

### Per-Tool Configs

- Tirzah: `config.yaml` (with `runtime:` section pointing at Hoglah, `mahalath_enabled`, etc.)
- Mahalath: `config.yaml` or equivalent.
- Hoglah: mainly driven by environment + its own `hoglah.db`.

Provide templates in `Noa/config-templates/windows/` and copy + substitute during install.

### UIs on Windows

- Mahlah and Mizpah are Vite + React apps.
- Installer should:
  1. Install Node (or use portable Node).
  2. Run `npm ci && npm run build` (or download pre-built `dist/`).
  3. Provide a small launcher (`.bat` that does `cd dist && npx serve .` or a simple Python http.server).
  4. Create desktop / Start Menu shortcuts that open `http://localhost:5273` (Mahlah) and `http://localhost:5274` (Mizpah) after starting the backends.

### Health Check Equivalent

Port `health/healthcheck.sh` to PowerShell (`healthcheck.ps1`):
- Check that selected CLIs are on PATH (via generated wrappers).
- Verify queue dir writable.
- Check Hoglah worker (service status or pidfile).
- Ping Mongo (via `mongosh` if present, or Docker exec).
- Optional: basic "tirzah ask" smoke test.

## Config Selection During Install

- Destination page (default `%LOCALAPPDATA%\Noa`).
- Optional advanced page: "Use custom root directory", "Port for Mongo", "External Mongo URI".
- "Install as current user only" vs "All users" (affects service type and shortcuts).

## Upgrade / Reconfigure Story

- Keep the same `versions.*.lock` mechanism.
- Provide `upgrade.ps1` that:
  - Backs up current `.env` and data.
  - Re-runs selected components with new pins.
  - Re-renders configs (without destroying user changes where possible).
  - Restarts services.

## Security & Isolation Notes

- Prefer per-user directories.
- Do not run services as SYSTEM unless absolutely necessary.
- When using embedded Python, the venvs live under the user's profile.
- Document how to point at a company Mongo or shared Ollama.
